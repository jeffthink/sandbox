# Dog Breed Guessing Game (`/dog-vote`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A mobile-first, per-dog breed-guessing game at `/dog-vote/<slug>`. It stores votes in a Google Sheet through a service account, shows the crowd's consensus after you vote, and switches to a scored reveal when the owner flips `revealed`.

**Architecture:**
- Pure game rules (`rules.js`) are unit-tested in isolation.
- A dependency-free Google layer (JWT auth + Sheets REST) sits under a cached store.
- SvelteKit server load and `+server.js` endpoints are the only callers of the store.
- Svelte 5 components under `src/lib/components/dog-vote/` render the flow.
- A `(sandbox)` route group isolates the existing sandbox layout so `/dog-vote` gets its own.

**Tech Stack:** SvelteKit 2, Svelte 5, D3 v7, vitest, `node:crypto`, `fetch`, Google Sheets REST API v4. No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-23-dog-vote-design.md`. Read it before any task. It defines the sheet layouts, scoring rules and UI behaviour this plan references.

## Global Constraints

- Code style:
  - JS with JSDoc, not TypeScript.
  - Tabs for indentation, as in existing files.
  - Tests are vitest `*.test.js` beside the source (`vitest.config.js` includes `src/**/*.test.js`).
- Every dog-vote `+page.server.js` / `+server.js` sets `export const prerender = false;`. The root `+layout.js` prerenders everything otherwise.
- Google is called only from `src/lib/server/**`, reading `$env/dynamic/private`. No Google URL, sheet ID or key ever reaches the browser.
- Env vars: `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY` (literal `\n` → newline), `DOGVOTE_<SLUG>_SHEET_ID`, `DOGVOTE_DEFAULT_SLUG`.
- Slug format: `^[a-z0-9]{2,32}$`.
- Validation limits:
  - name: trimmed, 1–50 chars;
  - guesses: 1–5, breed names unique case-insensitively, each 1–60 chars;
  - pct: integers 1–100, summing to exactly 100;
  - comment: ≤ 280 chars.
- Sheet ranges: `settings!A:B`, `votes!A:D`, `breeds!A:C`, `results!A1:B200`. Appends use `valueInputOption=RAW` and `insertDataOption=INSERT_ROWS`.
- Cache TTL is 15 000 ms per slug. A successful append invalidates that slug.
- Name normalization: trim, lowercase, collapse internal whitespace. Group normalization: name normalization, then strip a trailing ` group`.
- Consensus chart shows the top 8 breeds plus "Other".
- localStorage key is `dogvote:<slug>`. Every access is wrapped in try/catch.
- **PII:** tests, fixtures, README and `.env.example` use the fictional dog `biscuit`. Voter names in tests are fictional (`Ava`, `Ben`, …). "Luke" may appear only in `static/dog-vote/luke/`. Run `git diff --cached` before every commit and check for PII.
- Never render user-supplied text with `{@html}`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Spreadsheet-formula text** in a name, comment or free-text breed (`=HYPERLINK(...)`, `+1`, `@x`) must be stored literally. That means `RAW`, never `USER_ENTERED`, and it is shown as plain text. Tested in Task 5 (`appendRow` request body) and Task 2 (validateVote keeps it verbatim).
2. **A hand-edited `votes` tab** (blank rows, bad JSON, pct as `"50"` string, missing name) loads without crashing. Bad rows are skipped and the rest still count. Tested in Task 2 (`parseVoteRows`).
3. **A free-text breed that matches a listed breed in another case** (`"beagle "`) must merge with "Beagle" in consensus and scoring. Tested in Task 2 (validateVote canonicalizes) and Task 3 (scoring is case-insensitive).
4. **`revealed` = TRUE with zero votes, or with a results tab whose pcts don't sum to 100**, must render without errors: empty leaderboard, callouts omitted, scores still 0–100. Tested in Task 3.
5. **A returning visitor whose remembered name no longer has a vote in the sheet** (owner deleted the row) is shown the form again, not an empty crowd view. Tested in Task 2 (`crowdView` → `voted:false`) and wired in Task 9.

### Task 2: Core rules (validation, parsing, dedupe, consensus, crowd view)

**Files:** Create `src/lib/dogVote/normalize.js`, `src/lib/server/dogVote/rules.js` and `src/lib/server/dogVote/rules.test.js`.

**Interfaces (Produces):**
- `normalizeName(s: string): string` and `normalizeGroup(s: string): string`, both in `src/lib/dogVote/normalize.js`. They live outside `server/` so client components can import them too. `rules.js` re-exports them.
- `validateVote(input: unknown, breeds: Breed[]): { ok: true, vote: { name, guesses: Guess[], comment } } | { ok: false, errors: { name?: string, guesses?: string, comment?: string } }`
- `parseVoteRows(rows: string[][]): Vote[]`
  - Rows exclude the header.
  - Skips rows with a blank name, a missing timestamp, unparseable JSON, a non-array, or entries without a string breed and a finite number pct (numeric strings are coerced).
  - Logs with `console.warn` for each skipped row.
- `latestVotesByName(votes: Vote[]): Vote[]`: one per `normalizeName(name)`, max timestamp, with the later array index winning ties.
- `consensus(votes: Vote[], topN = 8): { all: Guess[], top: Array<Guess & { other?: true }> }`
  - The average is over **all** voters (0 for breeds a voter didn't pick).
  - Breeds are keyed by `normalizeName` and displayed with the first-seen spelling.
  - `all` is sorted descending, with ties broken alphabetically.
  - `top` is the first `topN` plus `{ breed: 'Other', pct: rest, other: true }` when rest > 0.
- `crowdView(votes: Vote[], name: string | null): { count: number, voted: boolean, consensus?: Guess[], votes?: Vote[] }`
  - `consensus` is the `top` list. `votes` is newest first.
  - The last two fields are present only when `voted`.

### Task 3: Scoring and reveal

**Files:** Create `src/lib/server/dogVote/scoring.js`, `src/lib/server/dogVote/scoring.test.js`

**Interfaces:**
- Consumes: `normalizeName`, `normalizeGroup`, `consensus` and the typedefs from `rules.js`.
- Produces:
  - `scoreGuess(guesses: Guess[], results: ResultRow[], breeds: Breed[]): number`, unrounded, between 0 and 100.
  - `buildReveal(votes: Vote[], results: Results, breeds: Breed[])`, returning:
    ```
    {
      leaderboard: Array<Vote & { score: number, rank: number }>,
      closest: (Vote & { score }) | null,
      wildest: (Vote & { score }) | null,
      crowdScore: number | null,
      popularMiss: { breed: string, voters: number, avgPct: number } | null
    }
    ```

Algorithm (from the spec; implement exactly):
1. A result row is a group iff `normalizeGroup(row.name)` equals `normalizeGroup(b.group)` for some breed `b`.
2. **Breed rows first:** `score += min(guessed[breed], actual)`. Record the used amount per guessed breed.
3. **Group rows:** sum `(guessed − used)` over guessed breeds whose mapped group matches, then `score += min(sum, actual)`.
4. **Rank:** score descending; ties go to the earlier `timestamp` of the counted (latest) row. `rank` is 1-based, with no shared ranks.
5. **Wildest:** the lowest score; ties go to the later timestamp. `closest` is `leaderboard[0]`.
6. **`crowdScore`:** `scoreGuess(consensus(votes).all, …)`.
7. **`popularMiss`:** among breeds guessed by anyone, those whose own name isn't a result breed row and whose mapped group isn't a result group row. Pick the one with the most voters, then the higher average pct over those voters. `null` if there isn't one.
8. **Zero votes:** everything is empty or null.

  - Caches per email until 60 s before `expires_in`.
  - A non-OK response throws `SetupError("Google rejected the service-account login: <error_description>")`.

### Task 5: Sheets client and cached store

**Files:** Create `sheets.js`, `sheets.test.js`, `store.js`, `store.test.js` in `src/lib/server/dogVote/`

**Interfaces:**
- Consumes: Task 4 (`getServiceAccount`, `getAccessToken`, `SetupError`) and Task 2 (`parseVoteRows`, `latestVotesByName`).
- Produces:
  - `batchGet({ token, sheetId, ranges, fetch }): Promise<string[][][]>`
    - Calls `GET …/v4/spreadsheets/{id}/values:batchGet?ranges=…`.
    - Returns `values ?? []` for each range.
  - `appendRow({ token, sheetId, range, row, fetch }): Promise<void>`
    - Calls `POST …/values/{range}:append?valueInputOption=RAW&insertDataOption=INSERT_ROWS` with body `{ values: [row] }`.
  - `class SheetsError extends Error { status: number }`
  - `parseSettings(rows, slug): Settings`
    - Keys are matched case-insensitively.
    - A missing `dog_name` throws `SetupError`.
    - `pronoun` defaults to `'they'`; an invalid value becomes `'they'`.
    - In `photos`, a bare filename becomes `/dog-vote/<slug>/<file>` and an `https://` URL is kept as-is. Values are split on commas and empties dropped.
  - `parseBreeds(rows): Breed[]`
    - Needs headers `breed` and `group`. `image_url` is optional.
    - Rows with a blank breed are skipped.
  - `parseResults(rows): Results`
    - Throws `SetupError` unless A1 normalizes to `revealed` and A2:B2 to `breed_or_group`/`pct`. The message mentions a possible shifted column.
    - `revealed` is true for `TRUE`/`true`/a checkbox's `TRUE`.
    - Rows with a non-numeric pct are skipped.
  - `loadDog({ env, fetch, slug }): Promise<DogData>`
    - Throws `SetupError` for config problems.
    - Unknown slugs are the caller's job; callers check `getDogConfig` first.
  - `appendVote({ env, fetch, slug, vote, now = () => new Date() }): Promise<'ok' | 'closed'>`
    - Reads `results!A1:B2` fresh, uncached. If revealed, returns `'closed'`.
    - Otherwise appends `[now().toISOString(), name, JSON.stringify(guesses), comment]` to `votes!A:D` and invalidates the slug's cache.
  - `_resetStoreCache(): void`

Map Google errors inside `loadDog` / `appendVote` to `SetupError`:
- **403:** "The sheet isn't shared with <email>. Share it as Editor."
- **404:** "No spreadsheet with that DOGVOTE_<SLUG>_SHEET_ID."
- **400 containing `Unable to parse range: <tab>`:** "Tab `<tab>` not found."
- **Missing header in `votes` or `breeds`:** "Tab `<tab>` needs headers: …"

Anything else re-throws as `SheetsError`.

- `addSlot(pcts: number[]): number[]`
- `removeSlot(pcts: number[], index: number): number[]`
- Invariants for all three:
  - integers;
  - each ≥ 1;
  - sum 100 for any length 1–5;
  - `value` is clamped to `[1, 100 − (n−1)]`;

  - rounding leftovers go to the largest (first such on ties);
  - `addSlot` gives the new slot `round(100 / (n+1))`, taken proportionally from the others;
  - `removeSlot` gives the removed share back proportionally.
